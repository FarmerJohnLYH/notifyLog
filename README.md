# 通知日志

将设备上所有其他 App 的通知预览持久化保存为本地日志。**纯离线、最小权限、事件驱动、极低占用。**

完整技术方案见 [TECH_DESIGN.md](TECH_DESIGN.md)。本 README 说明如何构建、安装、以及在小米 HyperOS 上完成保活设置。

### v0.1.5（2026-08-06）

多代理代码审计 + 回归测试共确认 18 项缺陷（7 项被驳回），本版全部修复：

**数据与隐私**

- **隐私：关闭云备份。** 原 `allowBackup="true"` 会把整个通知归档上传到 Google 云备份/设备迁移；现已关闭并显式声明排除规则。
- **数据丢失：去重改为时间窗（60s）。** 原去重仅按"最近 200 条不同内容"淘汰，没有时间维度：低频设备上，同一联系人几小时后再发一条内容相同的消息会被永久丢弃。现在只在 60 秒内视为重复刷新。
- **数据丢失：批量写入失败不再静默吞掉。** 整批失败时逐条重试，仍失败的计入"丢弃计数"并写日志；`onDestroy` 刷盘超时的数据会退回缓冲区等待下次写入，而非直接丢弃。
- **断档补采**：监听重新连接时，会把断档期间到达、且仍在通知栏中的通知补录（以断档起点为界，避免重复记录常驻通知）。
- 修复：导出写文件未截断，覆盖体积更大的旧导出会残留旧内容尾部。
- 修复：导出分页在捕获持续写入时会重复导出同一行；改为快照边界 + 键集游标。

**保活**

- **修复：force-stop 后前台服务与心跳永久失效**，而设置开关仍显示"已开启"。force-stop 会清除应用的闹钟与粘性服务记录，而原先只有开机广播会重新应用。现在进程启动时重挂心跳、回到前台时重启前台服务。
- 改进：断档时间点改由"捕获仍在工作"的心跳标记（每分钟一次，含被过滤的通知）确定，避免安静时段被误报为断档。

**界面**

- 修复：应用在后台期间捕获的记录，回到前台后不会出现（变更流仅在 STARTED 时工作）；现在恢复前台即刷新。
- 修复：在加载中切换筛选/搜索会被静默丢弃，导致筛选条与列表内容不一致。
- 修复：列表分页用 OFFSET，边捕获边滚动时会重复展示同一批记录；改为键集分页。
- 修复：导出格式/时间范围/应用筛选在系统回收并重建界面后丢失，可能导出错误内容；日期范围选择器在重建后确认无效。

### v0.1.4（2026-08-06）

- **修复（严重）：进程被杀后捕获永久静默失效。** 连接状态原先持久化在 SharedPreferences，而进程被系统杀死时 `onListenerDisconnected` 不会送达，`connected=true` 会永久残留；新进程因此误认为"正在记录"，既不重绑也不告警。现改为以进程内状态为准，并在新进程启动时补记断档（时间取最后一次成功落库的时刻）。这正是小米 HyperOS 强杀场景下最关键的一条。
- 修复：清空全部日志未重置去重缓存，导致清空后与旧记录内容相同的通知不再被记录。
- 改进：首页在"已授权但未连接"时请求重绑后会自动轮询复检，绑定成功即自动消除横幅。
- 新增：`test/` 完整回归测试计划与自动化脚本（功能 / 稳定性 / 内存·CPU），详见 [test/TEST_PLAN.md](test/TEST_PLAN.md)。

## 构建

**环境要求**：JDK 17、Android SDK Platform 36、Gradle 8.13（wrapper 或独立安装均可）。

```bash
./gradlew assembleRelease   # 或 assembleDebug
```

本 Windows 机器上（工具链已装好）：

```powershell
$env:JAVA_HOME="C:\Program Files\Eclipse Adoptium\jdk-17.0.20.8-hotspot"
$env:GRADLE_USER_HOME="C:\Android\gradle-home"   # 避开 IDE 对默认 ~/.gradle 的锁
C:\Android\gradle-8.13\bin\gradle.bat assembleRelease
```

产物：`app/build/outputs/apk/release/app-release.apk`（release 签名配置读取根目录 `keystore.properties`；无 keystore 时输出未签名包）。

> 版本说明：`compileSdk/targetSdk=36`、`minSdk=29`、Kotlin 2.1.20、AGP 8.11.1、Room 2.7.1。如首次 Sync 时 IDE 提示某组件有更合适的版本，按其建议微调 `gradle/libs.versions.toml` 即可。

## 安装与授权

1. 安装 APK。
2. 打开 NotifyLog，点击顶部横幅 →「通知使用权」，为 NotifyLog 打开开关。
3. 返回 App，横幅变为「正在记录」，之后新到达的通知会自动出现在列表。

核心功能只需**通知使用权**这一项特殊访问权，不申请网络、存储等任何运行时权限。

## 小米 HyperOS 3 保活设置（重要）

HyperOS 后台管控激进，即使已授权，进程被杀后也可能不自动恢复。请手动完成以下设置（详见 TECH_DESIGN §7）：

1. **自启动**：安全中心 → 应用管理 → NotifyLog → 权限 → 开启「自启动」。
2. **省电策略**：设置 → 应用设置 → NotifyLog → 省电策略 → 选「无限制」。
3. **后台锁定**：最近任务界面，下拉 NotifyLog 卡片并「锁定」，防止一键清理杀掉。
4. （可选）关闭系统对本应用的电池优化。

> 若发现记录空档，可在「设置 → 后台保活 → 系统保活设置」检查自启动与省电设置。

## 平台限制须知

- **验证码/OTP 遮蔽**：Android 15+ 起，系统会对普通通知监听器遮蔽验证码类通知内容，第三方 App 无法获取其正文（平台行为，非本 App 缺陷）。
- 日志明文保存在 App 私有目录（其他 App 无法访问）。MVP 暂未加应用锁/加密，后续里程碑再加。
- 日志默认**永久保留、不自动清理**；可在「设置 → 存储」开启自动清理或手动清理。
