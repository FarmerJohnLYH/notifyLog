# NotifyLog 回归测试计划

每个版本发布前完整执行一遍。自动化部分由 `regression.sh` 覆盖（Git Bash + adb + 模拟器），
人工部分（真机专项）在文末单列。执行结果按 `reports/v<版本>-<日期>.md` 存档。

**环境**：AVD `notifytest`（Android 36 / google_apis / AEHD 加速），或任意 API 29+ 设备。
google_apis 镜像支持 `adb root`，脚本用 sqlite3 直查应用私有数据库做精确断言；
无 root 的真机上跳过 DB 断言，退化为 UI 校验。

---

## A. 功能回归（自动化）

| 编号 | 用例 | 步骤 | 预期 |
|---|---|---|---|
| A1 | 基础捕获 | 注入一条唯一通知 | DB 行数 +1，标题/正文/包名/时间正确 |
| A2 | 内容去重 | 同 tag 同内容连发两次 | 只入库 1 条 |
| A3 | 更新捕获 | 同 tag 不同内容再发 | 新内容入库（每个变化版本都保留） |
| A4 | 空通知过滤 | —（由单测覆盖：无标题无正文跳过） | 不入库 |
| A5 | 列表实时刷新 | 应用前台停留在列表顶部时注入通知 | 新记录出现在可视区顶部 |
| A6 | 关键词搜索 | 注入含唯一 ASCII 标记的通知，搜索该标记 | 列表只显示匹配行 |
| A7 | 按应用筛选 | 筛选器选择某应用 | 只显示该应用记录，chip 可关闭恢复 |
| A8 | 长按操作 | 长按记录 → 复制/删除/排除 | 删除后行消失；排除后该应用不再入库 |
| A9 | 排除恢复 | 设置 → 已排除的应用 → 取消勾选 | 该应用恢复记录 |
| A10 | 导出 CSV（全部） | 导出 → CSV → 全部时间 → SAF 保存 | 表头`应用名,通知时间,通知内容`；行数=DB 行数；时间格式 `yyyy-MM-dd HH:mm:ss`；UTF-8 BOM |
| A11 | 导出 JSON（全部） | 导出 → JSON → 全部时间 | 合法 JSON 数组，条数=DB 行数，含全部字段 |
| A12 | 导出日期范围 | 选单日范围导出 | 只含该本地自然日的记录 |
| A13 | 前台服务加固 | 设置开启 | `isForeground=true`；常驻通知文本=「最近 1h 有 n 条通知」且 n 与 DB 一致；关闭后服务停止 |
| A14 | 常驻计数刷新 | 开启加固后注入通知（间隔>30s 节流） | 计数随之更新 |
| A15 | 心跳兜底 | 设置开启定时心跳 | `dumpsys alarm` 中存在本应用的 RTC_WAKEUP；关闭后消失 |
| A16 | 清空全部 | 设置 → 清空全部日志 → 确认 | DB 清零、占用刷新；**清空后重发相同内容可再次入库**（去重缓存须重置） |
| A17 | 手动清理 | 设置保留天数/条数后点立即清理 | 超限旧记录被删 |
| A18 | 深色模式 | `cmd uimode night yes/no` | 两种主题下界面正常、无重叠（截图留档） |
| A19 | 状态栏边衬 | 各页面截图 | 顶栏不与状态栏重叠（LogList/Settings/KeepAlive/Gaps） |

## B. 稳定性（自动化）

| 编号 | 用例 | 步骤 | 预期 |
|---|---|---|---|
| B1 | 突发风暴 | 30 秒内注入 100 条唯一通知 | 全部入库不丢（dropped=0）、无 ANR、logcat 无 FATAL |
| B2 | 进程被杀重绑 | root kill 应用进程 | 系统重绑监听（≤60s），期间断档写入 listener_event，「中断记录」可见 |
| B3 | 重启持久化 | `adb reboot` 后等待开机 | 监听自动恢复；已开启的前台服务/心跳由 BootReceiver 恢复；历史数据完整 |
| B4 | 长时间运行 | 模拟器挂机 30min+（可选，发版前抽查） | 无泄漏增长、无崩溃 |

## C. 内存 / CPU 占用（自动化采集，报告记录）

| 编号 | 指标 | 采集方式 | 基线（v0.1.3，模拟器 x86_64） |
|---|---|---|---|
| C1 | 空闲内存 PSS | 服务常驻、UI 关闭 5min 后 `dumpsys meminfo` | TOTAL PSS 记录于报告；关注环比 >20% 恶化 |
| C2 | UI 内存 PSS | 列表页打开时 | 同上 |
| C3 | 空闲 CPU | `top -n 3` 观察本进程 | ~0%（事件驱动，无轮询） |
| C4 | 风暴 CPU | B1 执行期间 `top` 采样 | 峰值记录于报告；关注环比恶化 |
| C5 | DB 增长 | B1 前后 DB 文件大小差 / 100 条 | 单条 ≈200–500B |
| C6 | APK 体积 | release APK 大小 | < 3 MB |

## D. 真机专项（人工，小米 HyperOS）

自动化无法覆盖、每次大版本在真机上人工确认：

1. 保活向导深链：自启动页、省电策略页能打开（或逐级降级到应用详情页），绝不崩溃。
2. 电池优化白名单弹窗可弹出并生效（`dumpsys deviceidle whitelist`）。
3. 一键清理/锁屏杀后台后监听恢复情况；「中断记录」与实际相符。
4. 常驻通知在 HyperOS 通知栏的展示与折叠行为。
5. Android 15+ OTP 遮蔽：验证码短信通知正文被系统遮蔽属平台行为，确认应用不崩溃。

## 执行方法

```bash
# Git Bash，模拟器已启动、adb 可用
cd test && ./regression.sh            # 全量
./regression.sh A B                   # 只跑指定组
./regression.sh --skip-reboot         # 跳过 B3（重启较慢）
```

脚本输出 PASS/FAIL 汇总并生成 `reports/` 草稿；FAIL 项修复后必须重跑全量确认无回归。
